# 用 Apifox AI 生成测试用例 —— 操作指南

> 目标：在 Apifox 「测试用例」页签里攒出一批**能通过**的用例，交作业时列表好看、老师能翻。
> ⚠️ AI 每生成一次都要调模型（花你的额度），**别裸跑**，按下面顺序来。

---

## 一、先配模型（省钱关键）

弹窗**右下角**可以换模型 / 供应商。**不要用 Apifox 默认的**，去配：

| 项 | 值 |
|---|---|
| Base URL | `https://open.bigmodel.cn/api/paas/v4/` |
| 模型 | `glm-4-flash` |
| API Key | 智谱开放平台自己申请 |

**GLM-4-Flash 目前永久免费、无 token 上限** —— 生成再多也不花钱。这事先办，不然白刷额度。

---

## 二、开始前必须先做的两件事

1. **关掉「校验响应」**：`项目设置 → 功能设置 → 响应校验设置`，
   把「校验响应 HTTP 状态码」「校验响应 Body 的数据结构」**两项都关**。
   （不关的话 AI 报的红和工具报的红混在一起，你分不清哪条该改。）
2. **先拿只读接口练手**：`GET /product/list`、`GET /mall`、`GET /product/edit?id=1`。
   **不要一上来就生成写接口**（新增/删除）的用例 —— 那些用例点「运行」会**真的发请求**，
   真的删你真数据。

---

## 三、AI 猜不到的"业务事实"（从源码里抠出来的，写死在提示词里）

这是整套操作的命门：**AI 不知道你的校验规则，只会按常识编。** 实测它编错了 4 处。
下面这些全部核对过源码，可以直接喂：

### 账号

| 账号 | 密码 | 权限 |
|---|---|---|
| `admin` | `123456` | 全部功能 |
| `user` | `123456` | 后台只读（工作台、商品列表、分类/品牌/订单只能看） |

**系统里只有这两个账号。** 禁止生成"密码含特殊字符""超长字符串""SQL 注入"之类 ——
账号是内存里固定的，这些输入只会走到「用户名或密码错误」，没有验证价值。

### 登录接口 `POST /login`

| 场景 | 状态码 | 页面显示 |
|---|---|---|
| 账号密码正确 | **302** → `/shop/mall` | — |
| `username` 为空 | **200** | `请输入用户名` |
| `password` 为空 | **200** | `请输入密码` |
| 账号或密码不匹配 | **200** | `用户名或密码错误` |

- `redirect` 是**可选**参数，允许为空；为空时同样跳 `/shop/mall`
- 站外地址（`//evil.com`、`https://baidu.com`）会被拦截，兜底回 `/shop/mall`
- `Location` 带上下文路径，形如 `/shop/xxx`

### 商品表单（新增 / 编辑）

| 校验 | 提示原文 |
|---|---|
| 价格是负数 | `价格必须是不小于 0 的数字` |
| 库存是负数 | `库存必须是不小于 0 的整数` |
| 品牌下拉选「其他」但名字没填 | `选了「其他」，记得把品牌名填上` |
| 图片超过大小上限 | `图片太大了，请压到 NMB 以内再传` |

### 品牌名校验（`DataStore.checkBrandName`，抽出来的唯一规则）

| 情况 | 提示原文 |
|---|---|
| 空 | `品牌名称不能为空` |
| 超过 20 字 | `品牌名称最多 20 个字` |
| 名字是 `__other__` | `这个名字不能用` |
| 含 `< > " '` | `品牌名称里不能有 < > " ' 这几个符号` |
| 重名 | `品牌【xxx】已存在` |

### 两个容易写错的枚举值

- 品牌「其他」的真实值是 **`__other__`** —— 不是中文「其他」
- 排序参数值是 **`priceAsc` / `priceDesc` / `stockDesc`** —— 不是 `price_asc`

## 四、提示词模板（直接复制进「输入更多要求」）

**第一段通用，每次都带；第二段只改接口名。**

```
【格式规矩】
本项目是 Servlet + JSP 的传统 Web 项目，接口不返回 JSON。
成功：返回 302 重定向，Location 指向目标页；失败：返回 200，并在 HTML 页面里显示中文错误提示。
校验响应已关闭，请不要写任何 JSON 相关的断言。
断言只允许用这三种：HTTP 状态码、Location 响应头、页面文本关键字。

【本次目标】
接口：GET /product/list
账号：admin / 123456（这个接口带登录态）
测试点：不传参数 / 传分类 / 传价格区间 / 传排序 / 关键字的正常与边界
期望：200，且页面里出现「商品列表」、商品名或「暂无」字样
```

### 各接口的「本次目标」替换示例

| 接口 | 本次目标怎么写 |
|---|---|
| 商品列表 | 见上 |
| 新增商品 | 账号 admin；正常提交 / 价格为负 / 库存为负 / 选「其他」没填品牌名；成功 302，失败 200 并显示对应提示 |
| 商品详情 | `GET /mall/item?id=1`；正常 id → 200 显示商品名；不存在的 id → 200 显示提示 |
| 权限 | 账号 user；`GET /product/add` → 403（Apifox 里页面上写「403」，不是 302） |
| 图片 | `GET /img?name=xxx`；正常文件名 → 200；`../../WEB-INF/web.xml` → 404；不存在的文件 → 404 |

## 五、生成之后：必须逐条点「运行」

**AI 生成的用例不能直接采纳，必须跑一遍。** 实测它常错在这几处：

| 错误类型 | 例子 |
|---|---|
| 编出不存在的账号 | 自己造了个"密码含特殊字符的合法账号" |
| 参数可选项当成必填 | 以为 `redirect` 必填，其实可选 |
| 错误文案猜错 | 写成"密码错误"而不是 `用户名或密码错误` |
| 漏掉上下文路径 | Location 期望 `/mall`，实际是 `/shop/mall` |
| 拿 302 的响应体做断言 | 302 的 body 是空的，断言它包含文字必红 |

处理方式：

- **通过** → 点「**采纳**」（才会复制进「测试用例」页签）
- **不通过但题目是对的** → 点开改断言的期望值，改对了再采纳
- **题目本身是错的**（比如账号不存在）→ 「**废弃**」

可以全选批量采纳 / 废弃。

---

## 六、数量建议

底部可以设**生成数量**，先填 **10~20**，别一上来拉满。
跑几轮摸清规律后，再按分组批量补。目标是**每个功能模块 3~8 条**，
覆盖「正常 + 边界 + 异常」三类，加起来几十条就足够交作业了。

---

## 七、一句话总结这套流程

1. 配免费模型（GLM-4-Flash）
2. 关校验响应
3. 只读接口先练手
4. 提示词里把**账号、文案、参数规则、上下文路径**全部写死
5. 逐条运行 → 改期望 → 采纳
6. 写接口的用例最后做，且跑完检查数据有没有被改坏
